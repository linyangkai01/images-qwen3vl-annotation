## 二、⚠️ 方案中的事实错误（我已实测核实，需修正而非研究）

### A1 · P1「私有 VLM 端点 403」是**误判**

**方案原文**：「P1 私有 VLM 端点持续可用 —— ⚠️ **已被证伪（403）**，最大风险」
并据此提出「优化 4 · VLM 端点抽象成可替换 Provider（当前硬依赖）」。

**我的实测（用项目自己的代码路径，非 curl）**：

```
provider=private_vlm
annotator=PrivateVlmAnnotator
OK 检出=3          ← 调用成功
```

**根因**：403 来自**用 curl 手工构造请求时 token 少读了 3 个字符**
（token 文件是 `export LAB_VLM_TOKEN=xky-...`，curl 读法得 16 字符，项目代码读法得 19 字符）。

**修正建议**：
1. P1 状态改为「**正常**」，风险等级下调
2. 「优化 4（端点抽象）」的**动机不成立** —— 可作为**架构改进**保留，但不应以"当前硬依赖已瘫痪"为由
3. **通用教训**：探测外部服务**必须用项目自己的调用路径**，不要用 curl 手工构造

### A2 · P3「相机静止与否未验证」——**我已验证，结论是运动**

**方案原文**：P3 状态「未确认（相机静止与否也未验证）」。

**我的实测（两种独立方法）**：

```
方法一 · 边缘区域像素差（背景代理）: 35.2 / 34.6 / 28.3 / 37.0（阈值 8）
方法二 · 相位相关全局位移:            7.5 / 16.4 / 5.4 / 8.0 px（阈值 5）
→ 4 段全部为「明显运动」
```

**修正建议**：P3 状态改为「**已验证为运动相机**」，并据此**放弃「铅垂投影 + 地面平面」路线**
（该路线要求静态相机下相机高为唯一未知数）。

## 三、⚠️ 方案识别但未给解法的问题（需深度研究）

### B1 · 【最紧急】数据泄漏 —— 方案识别了，但需立即修复并研究影响

**方案原文（优化 5）**：`dataset.py:466-476` 按 `relative_path` 排序后按数量切一刀 → 泄漏。

**我的独立核实（已量化）**：

```
train 各 source: 161134:70 / 161153:22 / 161157:53 / 161201:51
val   各 source: 161201:56                    ← val 只有 1 个 source！
★ 161201 同时出现在 train 和 val
```

**确认两个问题**：

1. **泄漏**：`161201` 的 train 帧（前 51）与 val 帧（后 56）**是同一段视频的相邻时段**
   （相邻帧间隔约 4.6 秒）→ val 帧与 train 末帧几乎同一画面
2. **评估偏差**：**val 只覆盖 1 个 source** → 完全不具代表性

**影响**：训练期 val 指标（mAP50 0.092）**既虚高（泄漏）又偏斜（单 source）**，不能用于任何调参判断。
（holdout 9 帧独立，不受此影响）

#### 📋 深度研究任务书 B1

**研究方向**：视频帧数据集的**无泄漏划分策略**（针对稀疏抽帧的监控视频）

**必须回答的问题**：
1. 按 `source_id` 做 GroupShuffleSplit 后，**train/val 时间边界处需要多大缓冲**才能消除泄漏？
   （当前帧间隔 4.6 秒；缓冲取 1 帧？30 秒？1 分钟？请给出依据）
2. 若某类样本只集中在少数 source（如 `balance_beam` 只在 1~2 段出现），
   **按 source 分组会让该类在 val 中消失** —— 这种"分组与分层的冲突"如何权衡？
3. 稀疏抽帧（0.22 fps）下，**同一事件的相邻帧是否应强制同组**？如何界定"同一事件"？

**交付要求**：
1. **一份划分策略说明**（含伪代码），明确：分组依据、缓冲大小及依据、分层与分组的冲突解法
2. **泄漏检测方法**：给出可自动运行的检验（如"train/val 跨集最近帧时间间隔"的统计 + 阈值）
3. **对现有 `full-v3` 数据集的重新划分**（`full-v4`），并**对比泄漏前后**的训练期指标差异
   （用于量化"泄漏让指标虚高了多少"）
4. **验收标准**：重新划分后，`train/val 跨集最近帧时间间隔 ≥ 缓冲值` 的断言通过；
   且报告 val 的 source 覆盖数 ≥ 3
