# 标注链路提效方案（抽帧 → 初筛 → 人工复核）

> 生成时间：2026-09-25
> 依据：实读 `video_decode.py` / `active_learning.py` / `project.hoist.json` + 实测跑批数据
> 结构：**现状瓶颈 → 具体改进措施 → 预期收益 → 实施成本与优先级**
> 每项含：可执行改动点 / 前提条件 / 潜在风险 / 验证方式

---

## 〇、先纠正一个问题：抽帧不是瓶颈，别优化错地方

老总问"加速抽帧"。**但实测抽帧耗时只有 13.9 秒**（4 段视频共 1908 秒素材）。

全链路耗时实测：

```
抽帧（1908 候选 → 415 帧）    13.9 秒      占 0.02%
YOLO 初检（415 帧）           约 3 分钟     占 0.3%
VLM 复核标注（323 帧）        15.9 小时     占 97.5%   ← 唯一瓶颈
训练（50 epoch）              10.6 分钟     占 1.1%
```

**抽帧即使优化到 0 秒，也只能省 13.9 秒。**

**真正该做的是「减少帧数」** —— 因为每多一帧，下游要付 **176 秒**的 VLM 标注成本。抽帧环节的价值不在"快"，而在"**准**：用最少的帧覆盖最多的信息"。

所以本方案把"加速抽帧"重新定义为：**在不丢关键帧的前提下压低帧数**。

## 一、现状瓶颈

### 1.1 当前链路与参数（实测值）

```
抽帧两段式：
  sample_frames  : ffmpeg 按 sample_fps=1.0 均匀抽 → 1908 候选帧
  select_keyframes: 六步筛选 → 415 帧（保留率 21.7%）

六步筛选参数（project.hoist.json / keyframe）：
  motion_min_ratio        0.002     低于此运动比 → 判静丢弃
  pixel_delta_threshold   25        像素差阈值
  dedup_hamming_threshold 4         与【上一个保留帧】的 aHash 汉明距离 ≤4 → 判重丢弃
  phash_size             8
  scene_change_threshold 0.4        直方图差 ≥0.4 → 场景切换，强制保留
  max_keyframes          400
  min_gap_seconds        2.0
  force_keep_labels      [person, hook, rigging, overhead_crane, load]

初筛与复核参数（pipeline）：
  min_detection_confidence    0.25   YOLO 初检阈值
  review_confidence_threshold 0.8    复核判定阈值
  include_empty_frames        False
```

### 1.2 四个瓶颈（按严重度排序）

**瓶颈 1（最严重）：复核判据几乎恒真 —— 99.7% 进队列的直接原因**

`active_learning.py:73-79` 的算法：

```python
confidences = [item.confidence for item in record.qwen_detections]
min_conf = min(confidences)                      # ← 取【最低】置信度
low_conf = (threshold - min_conf) / threshold    # threshold = 0.8
```

两个问题叠加：

1. **用 `min`（最保守聚合）**：一帧里只要有**任何一个框**置信度 < 0.8，整帧判为可疑。VLM 输出的框动辄十几个，几乎不可能全部 ≥0.8。
2. **阈值 0.8 一刀切**：把易检的 `person`（大目标）和极难的 `helmet`（10.8px 小目标）用同一个门槛。helmet 的置信度天然就低，用它去卡整帧必然全中。

**结论：这不是检测器不准，是判据设计错了。** 换任何更准的初检器都救不了——因为判据本身恒真。

**瓶颈 2：去重只比"上一帧"，漏掉非相邻重复**

`dedup_hamming_threshold` 只与**上一个保留帧**比较。吊装作业画面变化慢，相隔几十帧的画面可能高度相似，但因为是"非相邻"，不会被判重。

**瓶颈 3：VLM 标注 176 秒/帧，且当前端点 403**

单帧成本降不下来（thinking 权重），又暂时调不了端点。所以唯一出路是**减少帧数**。

**瓶颈 4：没有 ground truth，准确率无法直接测**

197 条隐患里 92 条标"待确认"，而"准确率/漏检率"目前**没有任何真值可对照**。要量化这两个指标，必须先建立验证集（见措施 6）。

## 二、具体改进措施

### 措施 1 · 重写复核判据（最高优先级，零成本）

**可执行改动点**

`active_learning.py` 的 `score_uncertainty` 改两处：

**1a. 聚合方式：`min` → 按类分档 + 只看关键类**

不再用"所有框的最低置信度"，改为：

```
只检查「对隐患判定有影响」的框（force_keep_labels 那 5 类 + helmet/vest）
其他装饰性框的低置信不影响整帧判定
```

**1b. 阈值按类分档（不再一刀切 0.8）**

阈值**不要拍脑袋定**，用已有数据标定。方法：

```
1. 统计 323 帧标注里每个类的置信度分布
2. 取该类的 P25 分位数作为 pass_threshold
   → 含义：保证该类 75% 的框能自动通过
3. 对样本极少（<20 框）的类，阈值下调一档或强制送人工
```

按类别难度预期会分成三档：

```
易检（大目标，形态固定）：person / overhead_crane / load / balance_beam
  → pass_threshold 预期 0.85 上下
中检（形态多变）：hook / rigging / spreader
  → 预期 0.60 上下
难检（小目标）：helmet（10.8px）/ vest（25.6px）
  → 预期 0.45 上下
```

**1c. 三态判定规则（自动通过 / 自动拦截 / 人工复核）**

```
auto_pass（自动通过，不进人工队列）：
  ① 帧内所有关键类框的置信度 ≥ 该类 pass_threshold
  ② 且 VLM 与初检器的框集合一致（无新增 / 无删除 / 无大幅调整）
  ③ 且 该帧的类别组合是已见过的常见组合

auto_reject（自动拦截，直接丢弃不标注）：
  ① 空帧（无任何有效目标）且运动比极低
  ② 或 annotation_error（标注失败）
  ③ 或 与该源已保留帧的嵌入相似度 > 阈值（重复）

needs_review（人工复核）：
  其余全部
```

**前提条件**：需要先把 323 帧标注的置信度分布统计出来（一次性，几分钟）。

**潜在风险**
- 自动通过会**放过一部分错误标注**。这是必然的取舍：人工复核量 vs 标注准确率。
- 缓解：对 auto_pass 的帧做**事后抽检**（见验证方式），用抽检错误率反过来校准阈值。

**验证方式**
```
1. 用新判据重跑 323 帧，统计三态占比
   目标：needs_review 从 322 帧降到 60~100 帧
2. 从 auto_pass 的帧里随机抽 30 帧做人工检查
   统计：框错误率、漏标率
   若错误率 > 5% → 上调 pass_threshold 重跑
3. A/B：新旧判据各跑一遍，对比最终训练出来的模型指标
   （这是终极验证：人工量少了，模型指标不能掉）
```

### 措施 2 · 全局去重与聚类（压缩帧数，主要收益）

**可执行改动点**

现状 `dedup_hamming_threshold` 只比**上一帧**。改为**两阶段去重**：

```
阶段 A（保留现有）：相邻帧 pHash 去重 —— 快，成本低，保留
阶段 B（新增）：全局嵌入聚类去重
  1. 对 415 帧用现成视觉编码器提特征
     （可用 CLIP / DINOv2；或退化方案：直接用现有 pHash 但做全局两两比较）
  2. 聚类（如 DBSCAN 或层次聚类）
  3. 每簇只保留 1~2 个代表帧（如簇内中位数帧 + 运动最大的帧）
  4. 保护规则：含稀有类（spreader / pallet / hook）的帧强制保留，不参与去重
```

**前提条件**
- 需要一个视觉编码器（CLIP/DINOv2）。**训练脚本可装包，主链路零依赖约束不受影响**（去重脚本属于离线工具）
- 或退化方案：纯 pHash 全局两两比较（415 帧只需 ~86k 次比较，秒级），**零依赖**

**潜在风险**
- **去重会损失稀有类样本** —— 这是最大的风险。spreader 只有 15 框、pallet 2 框，去重时误删会直接归零
- 缓解：`force_keep_labels` 扩展为"含稀有类的帧不参与去重"，或去重后校验各类框数损失 ≤5%

**验证方式**
```
1. 去重后统计：帧数、各类框数
   硬指标：任何一类的框数损失 > 10% → 去重过猛，回退
2. 用去重前后的数据集各训一版，对比逐类 mAP50
   若稀有类明显下降 → 说明去重删掉了关键样本
3. 人工抽查被删帧：随机抽 20 个被去重的帧，看是否真的冗余
```

### 措施 3 · 抽帧策略调整（低优先，但给出依据）

**诚实结论：这里能省的只有几秒，价值不大。但策略仍要调对，因为它决定下游帧数。**

**可执行改动点**

```
现状：sample_fps = 1.0（均匀）→ 1908 候选 → 415 保留

可选调整：
  a) 自适应 sample_fps：低运动时段 0.5，高运动时段 1.0
     收益：候选帧数 -30%，抽帧耗时几乎不变（13.9s 本来就快）
     风险：低运动时段可能漏掉"人缓慢走进危险区"这类慢动作隐患 ← 真实风险
     建议：不做。吊装作业的关键动作往往是缓慢的，降采样会漏。

  b) 保持 sample_fps=1.0，把降量放在后段（措施 2）
     建议：采纳。因为抽帧便宜、标注贵，宁可多抽再筛。

  c) 并行处理：4 段视频并行抽帧
     收益：13.9 秒 → 约 5 秒（4 核并行）
     成本：低
     建议：可做可不做，收益绝对值太小
```

**调整依据（明确回答老总的问题）**

抽帧频率的调整依据**不是"越快越好"，而是"下游成本 vs 漏检风险"**：

```
每多抽 1 帧的成本  ≈ 176 秒（VLM 标注）
每少抽 1 帧的风险  = 可能漏掉一个隐患事件

→ 所以抽帧频率应该【宁密勿疏】，降量靠后段筛选
→ 唯一例外：如果某段视频被判定为"低风险时段"（无吊装作业，如纯空场），
   可以整段降采样或跳过
```

**触发条件（建议新增）**

```
按场景而非按时间触发：
  - 场景切换（scene_change_threshold ≥ 0.4）→ 强制保留（现状已有）
  - 新增建议：检测到 overhead_crane / load 出现 → 该时段提高采样密度
  - 新增建议：连续 N 帧无 person 且无 load → 该时段降采样
```

### 措施 4 · 双源一致性自动放行

**可执行改动点**

用**初检器（YOLOE/YOLO-World）的框** 与 **VLM 的框** 做对比：

```
对每一帧计算两个来源的框匹配情况（IoU + 类别）：
  一致率 = 匹配的框数 / max(两源框数)

一致性 ≥ 0.8 且两源置信度都达标 → auto_pass（自动放行，不进人工队列）
一致性 < 0.5                    → needs_review（优先送人工）
中间地带                        → 按置信度分档决定
```

**前提条件**：需要先落地初检器替换（YOLOE，见调研报告 P1-1）。
**退化方案**：用现有 YOLO 初检框与 VLM 框比（虽然 YOLO 召回低，但**一致性高本身就是强信号**）。

**潜在风险**
- 两个来源**同时错**（都漏检同一个物体）→ 一致性高但都错
- 缓解：对 auto_pass 的帧保留 5~10% 抽检

**验证方式**
```
统计一致性分布，看 auto_pass 占比
抽检 auto_pass 帧的错误率（同措施 1）
```

---

### 措施 5 · 复核队列的优先级排序（让人工先看最该看的）

**现状**：`build_priority_queue` 已有不确定性打分，但因为 99.7% 都进队列，排序失去意义。
**改动**：队列压缩后，排序才有价值。按以下优先级：

```
P1 - 标注失败（annotation_error）
P2 - 双源严重不一致
P3 - 含稀有类且低置信（spreader / pallet / hook）
P4 - 含关键类且低置信（person 在 load 下方等高风险组合）
P5 - 一般低置信
```

---

### 措施 6 · 建立验证集（准确率/漏检率能被测出来的前提）

**这是唯一能让"准确率"从口号变成数字的办法。**

```
从 323 帧中按视频源分层抽样约 155 帧（31 视频源 × 5 帧）
3 人独立标注 + 第三人仲裁
用潜类别模型（Dawid-Skene）估计真值
→ 得到：VLM 标注的准确率、漏检率、各类别 F1
```

**前提条件**：需要人工预算（约 155 帧 × 3 人）。
**这个不做，措施 1~4 的"准确率提升"都无法证实。**

## 三、预期收益（量化目标）

### 3.1 现状基线（实测，作为对照）

```
素材：4 段视频，1908.53 秒
抽帧候选：1908 帧（sample_fps=1.0）
抽帧产出：415 帧
抽帧耗时：13.9 秒
YOLO 初检：415 → 323 候选（657 框）
VLM 复核标注：323 帧（1553 框），15.9 小时
人工复核队列：322 帧（占候选 99.7%）
准确率/漏检率：无真值，无法测量 ← 必须标注为"未知"
```

### 3.2 分阶段收益目标

**阶段 1 · 改复核判据（措施 1，成本 0.5 天）**

```
人工复核帧数：322 → 60~100 帧        目标降幅 70~80%
抽帧耗时：不变（13.9 秒）
准确率：不变（只是不再把确定帧送人工）
VLM 耗时：不变
```

**阶段 2 · 去重与聚类（措施 2，成本 1~2 天）**

```
抽帧产出：415 → 200~250 帧           目标降幅 40~50%
VLM 标注耗时：15.9h → 8~10h          目标降幅 40~50%
人工复核帧数：在阶段 1 基础上再降 40~50% → 30~60 帧
风险指标：任何一类的框数损失 ≤ 10%（超过即回退）
```

**阶段 3 · 双源一致性（措施 4，成本 2~3 天，依赖初检器替换）**

```
人工复核帧数：再降 50% → 15~30 帧
初检召回：657 框 → 1200~1500 框（12 类全覆盖）
```

**阶段 4 · 建立验证集（措施 6，成本 1~2 天 + 人工预算）**

```
产出：VLM 标注准确率、漏检率的实测数字（当前为空）
用于：校准措施 1 的阈值，验证措施 2/4 是否真的没丢东西
```

### 3.3 汇总目标

| 指标 | 现状 | 目标 | 降幅 |
|---|---|---|---|
| 抽帧耗时 | 13.9 秒 | 13.9 秒（不变） | — |
| 抽帧产出帧数 | 415 | 200~250 | -40~50% |
| VLM 标注耗时 | 15.9 小时 | 8~10 小时 | -40~50% |
| 人工复核帧数 | 322（99.7%） | 15~60（5~20%） | **-80~95%** |
| 初检召回（框数） | 657 | 1200~1500 | +80~130% |
| 准确率 / 漏检率 | **未知** | 实测得出（阶段 4） | — |

**⚠️ 诚实说明**：抽帧耗时**不降**——因为它本来就只要 13.9 秒，不是瓶颈。强行"加速抽帧"是把力气用错地方。真正的收益在**帧数**和**复核量**。

```
第 1 步（本周）：措施 1 + 措施 6 并行启动

  - 措施 6 同步启动，因为人工标注需要时间，越早开始越好

第 2 步：措施 2（去重），但必须带"各类框数损失 ≤10%"的硬门禁

第 3 步：措施 5（队列排序）

第 4 步：措施 4（依赖 YOLOE 落地）

```

## 五、每项措施的前提 / 风险 / 验证（速查）

**措施 1 · 重写复核判据**
- 前提：统计 323 帧各类置信度分布（几分钟）
- 风险：自动通过会放过错误标注
- 验证：① 三态占比（needs_review ≤100 帧）；② auto_pass 帧抽 30 帧查错误率；③ 新旧判据各训一版比模型指标

**措施 2 · 全局去重聚类**
- 前提：视觉编码器（可退化到纯 pHash 全局比较，零依赖）
- 风险：**误删稀有类样本**（spreader 15 框、pallet 2 框）
- 验证：① 各类框数损失 ≤10%（硬门禁）；② 去重前后各训一版比逐类 mAP50；③ 抽 20 个被删帧看是否真冗余

**措施 3 · 抽帧策略**
- 前提：无
- 风险：降采样会漏掉缓慢动作（人缓慢走进危险区）
- 验证：对比降采样前后的隐患检出数
- **建议不做**

**措施 4 · 双源一致性**
- 前提：初检器替换为 YOLOE（或退化用现有 YOLO 框）
- 风险：两源同时漏检 → 一致性高但都错
- 验证：auto_pass 帧 5~10% 抽检

**措施 5 · 队列优先级**
- 前提：措施 1 先把队列压下来，否则排序无意义
