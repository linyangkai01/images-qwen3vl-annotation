## 二、核心发现：D-5-3 的判据写反了

这是本次最重要的一个发现。

### 现象

`geometry.py:163` 的 `find_person_under_load` 判据是 `contains(load, person)`：

```python
def contains(outer, inner) -> bool:
    # 内框中心落在外框内，且内框面积被外框覆盖 ≥ 85%
```

**这判的是「人被吊物框住」，不是「人在吊物下方」。**

### 为什么这是错的

`taxonomy.py:287` 里 D-5-3 的规范名是 **「人员站在吊物下方/上方」** —— 两个字，代码只覆盖了后一个。

真实吊装画面（地面视角或监控斜视角）：

```
   ┌─────────┐  ← load 框（吊物挂在高处，画面上半部）
   └─────────┘
        |
        |        ← 中间是空的，人框在下面
     ┌──┐
     │  │        ← person 框（人站地面，画面下半部）
     └──┘
```

人框和 load 框**完全不重叠** → `contains` 永远返回 `False` → 一条结论都产不出来。

`contains` 只在**正上方俯拍**（吊物遮挡住下方的人）时才成立。珠海那批视频不是这个视角。

### 为什么测试没发现

`tests/test_layers.py:104` 的测试用例构造的是：

```python

person = (0.4, 0.4, 0.6, 0.6)   # 完全在大框内部
self.assertTrue(geometry.contains(load, person))
```

**测试构造的是「人被吊物包住」的俯拍场景，所以过了。** 测试通过 ≠ 真实场景能判出来。这是典型的「看起来完成了、实际是死代码」。

### 影响

- D-5-3 有 **85 条**（占 197 条的 43%，占 92 条待确认的 92%）
- 这 85 条全部被标「需人工确认，未经检测验证」

## 四、方案一：修 D-5-3 判据（最高优先级，1 天）

### 设计思路

分**两个视角分支**，分别标注判定依据，避免重蹈「只覆盖一种视角」的覆辙：

- **分支 A `top_down`（俯拍 / 人在吊物上）**：保留现有 `contains` 语义
- **分支 B `ground`（地面视角 / 人在吊物下方）**：新增 —— **水平投影重叠 + 垂直位置**

### 分支 B 的判据（三条件同时满足）

1. **水平投影重叠率** `HOR ≥ 0.5`
   `HOR = 水平区间交集 / min(人宽, 吊物宽)`
   用 `min` 而不是 `max`：人比吊物窄时看人是否完全在带内，人比吊物宽时看吊物投影是否落在人身上 —— 两种情况都该判 1.0，物理才对。

2. **人在吊物下方**：`person 中心 y > load 中心 y`（归一化坐标，y 向下增大）

3. **置信度门槛**：`person.score ≥ 0.4` 且 `load.score ≥ 0.4`

**不设垂直间隙上界** —— 吊物挂多高不影响危险性，人只要在同一铅垂带里就危险。间隙值仍记录进证据，供人工看。

### 代码补丁（可直接用）

加到 `industrial_hazard_coldstart/layers/geometry.py`：

```python
#: 「人在吊物下方」判定的水平投影重叠率阈值。
MIN_HORIZONTAL_OVERLAP: float = 0.5

#: 参与几何判定的最低检测置信度（低于此不判，避免用噪声框下结论）。
MIN_JUDGE_SCORE: float = 0.4


def horizontal_overlap_ratio(person: Detection, load: Detection) -> float:
    """人的水平投影与吊物铅垂投影带的重叠率（0–1）。

    分母取 ``min(人宽, 吊物宽)``：人比吊物窄时衡量「人是否完全在带内」，
    人比吊物宽时衡量「吊物投影是否落在人身上」——两者都该判 1.0。
    """
    px1, _py1, px2, _py2 = person.bbox
    lx1, _ly1, lx2, _ly2 = load.bbox
    overlap = max(0.0, min(px2, lx2) - max(px1, lx1))
    denom = min(px2 - px1, lx2 - lx1)
    if denom <= 0.0:
        return 0.0
    return overlap / denom


def fall_zone_evidence(
    person: Detection,
    load: Detection,
    hor_threshold: float = MIN_HORIZONTAL_OVERLAP,
    min_score: float = MIN_JUDGE_SCORE,
) -> dict[str, Any] | None:
    """判定「人是否处于吊物危险区」，返回证据字典；不成立返回 ``None``。

    两个视角分支：
      - ``top_down``：俯拍或人站在吊物上 —— 人框被吊物框包含（原 ``contains`` 语义）
      - ``ground``：地面视角 —— 人在吊物下方且水平投影重叠达标
    """
    if person.confidence < min_score or load.confidence < min_score:
        return None
    _lx1, _ly1, _lx2, load_y2 = load.bbox
    person_y1 = person.bbox[1]

    # 分支 A：俯拍 / 人在吊物上方（保留原语义）
    if contains(load, person):
        return {
            "view": "top_down",
            "hor": round(containment_ratio(load, person), 6),
            "gap": round(person_y1 - load_y2, 6),
            "rule": "containment",
        }

    # 分支 B：地面视角 / 人在吊物下方
    hor = horizontal_overlap_ratio(person, load)
    if hor < hor_threshold:
        return None
    _pcx, pcy = _center(person.bbox)
    _lcx, lcy = _center(load.bbox)
    if pcy <= lcy:  # 人不在吊物下方
        return None
    return {
        "view": "ground",
        "hor": round(hor, 6),
        "gap": round(person_y1 - load_y2, 6),
        "rule": "horizontal_projection",
    }
```

然后把 `find_person_under_load` 改成用它（替换 `geometry.py:163-194`）：

```python
def find_person_under_load(
    dets: Iterable[Detection],
    aspect_ratio: float = 1.0,
) -> list[RelationFinding]:
    """发现「人员站在吊物下方 / 上方」（``D-5-3``）。

    对每个 ``load`` × ``person`` 组合调用 :func:`fall_zone_evidence`；
    成立则产出一条结论，``notes`` 记录视角分支与几何数值，便于人工复核。
    """
    _ = aspect_ratio
    detections = list(dets)
    findings: list[RelationFinding] = []
    for load in _by_label(detections, "load"):
        for person in _by_label(detections, "person"):
            evidence = fall_zone_evidence(person, load)
            if evidence is None:
                continue
            findings.append(
                _finding(
                    HAZARD_PERSON_UNDER_LOAD,
                    "person_under_load",
                    [load, person],
                    f"视角={evidence['view']} 判定={evidence['rule']} "
                    f"水平投影重叠={evidence['hor']:.3f} 垂直间隙={evidence['gap']:.3f}"
                    f"（归一化）；本期留位，不接入交付指标。",
                )
            )
    return findings
```

## 六、方案三：评估口径（0.5 天，纯报告层，不动模型）

### 6.1 加 GT 门槛

`pallet` 在评估集里 gt=2，单个框命中/漏检就让 AP 在 0↔1 之间跳。这类**不该报 mAP**，改报「命中 / 漏检计数」。

**门槛建议：gt ≥ 10 的类才进宏平均。**

### 6.2 加 bootstrap 置信区间

**按图像重采样，不要按框重采样** —— 同图内的框不独立，按框采样会低估方差。

```python
def bootstrap_map_ci(per_image_results, n_boot=1000, alpha=0.05):
    """image-level bootstrap：按图像有放回重采样，返回 mAP 的 95% CI。"""
    import random
    n = len(per_image_results)
    scores = []
    for _ in range(n_boot):
        sample = [per_image_results[random.randrange(n)] for _ in range(n)]
        scores.append(aggregate_map(sample))
    scores.sort()
    lo = scores[int(n_boot * alpha / 2)]
    hi = scores[int(n_boot * (1 - alpha / 2))]
    return lo, hi
```

CI 宽度解读：`<0.05` 稳定 / `0.05~0.10` 谨慎比较 / **`>0.10` 不可比**。

9 帧 holdout 的 CI 宽度会接近 1.0 —— 那就**在报告里如实写「CI 极宽，仅作方向性参考」**，别拿它做验收。

### 6.3 验收改成四层

现在的「档内取最差」在 1:140 不均衡下等价于永远 fail。改成：

1. **安全关键类双门限**：整体（样本加权）达标 **且** `person`/`helmet`/`vest`/`harness` 逐类 ≥ 阈值；其余类只要求「不回归」
2. **GT 门槛过滤**：gt < 10 的类不参与打分
3. **CI 门限**：要求 **CI 下界** ≥ 阈值，杜绝噪声点估计过关
4. **双轨门禁**：冻结 holdout 做「无回归」，31 帧大评估集做「绝对达标」

### 6.4 补一个 COCO 事实

COCO 宏平均规则：**无 GT 的类被排除出均值；有 GT 但零检出的类计 0 并计入均值**。

所以那 7 类为 0 是**真实缺陷**，不能拿「缺类忽略」辩解。但 `overall=0` 把 person 0.667 / balance_beam 0.764 的进展全掩盖了 —— 必须三层同时报：micro-mAP 为主 + 逐类 AP 附 gt 数 + macro 注明被几类零值主导。
