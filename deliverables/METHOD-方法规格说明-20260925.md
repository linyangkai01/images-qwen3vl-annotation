## 一、M1 · 事件级去重（最高优先级）

### 1.1 为什么必须做

当前报告的 197 条是**帧级计数**——同一个隐患在连续帧里会被重复记录。实测：

```
帧级 197 条 → 事件级 159 条（推荐口径）
D-1-3（吊链与硬质表面接触）：26 条 → 12 个事件
  其中最长的一个事件跨 22 帧、持续 56 秒（t=14~70s）
```

D-1-3 的 26 条里有 22 条其实是**同一次持续状态**。不合并会严重夸大。

### 1.2 算法规格（推荐方案）

**用「帧序号连续性」判定，不要用「时间间隔」。**

**理由**：本项目用的是**基于内容变化的关键帧提取**，抽帧**非均匀**。若按秒数定阈值，间隔分布很宽时阈值没有客观依据。而帧序号连续性直接对应"中间有没有被跳过的帧"，与抽帧是否均匀无关。

**算法**：

```
输入：hazards 列表（每条含 hazard_id、source_frame、source_id）
      source_frame 形如 "<源名>/frame_<帧序号:06d>_<时间戳:09.3f>.png"

1. 从 source_frame 解析出 (source, frame_index, timestamp)
2. 按 (hazard_id, source) 分组
3. 组内按 frame_index 升序排序并去重
4. 扫描：若 当前.frame_index - 上一个.frame_index <= TOL
         则并入当前事件
         否则结束当前事件、开启新事件
5. 每个事件记录：
   {hazard_id, source, start_frame, end_frame, frame_count,
    t_start, t_end, duration_sec, representative_frame}
```

**参数 TOL = 2**（容忍 1 帧漏检）。

**TOL 取值依据**（实测敏感性，必须让编码组和甲方都看到）：

```
TOL=1: 事件总数 197  D-5-3 = 85 (43.1%)   ← 完全不合并
TOL=2: 事件总数 159  D-5-3 = 69 (43.4%)   ← 【推荐】
TOL=3: 事件总数 155  D-5-3 = 67 (43.2%)
TOL=5: 事件总数 134  D-5-3 = 59 (44.0%)
```

- TOL=1 太严：VLM 漏检一帧就会把一个事件劈成两个
- TOL=5 太松：会把独立的两次事件合并
- **TOL=2 是折中：容忍单次漏检**

⚠️ **必须向甲方说明的诚实点**：TOL 从 1 到 5，事件总数在 197~134 之间变化。**D-5-3 的绝对数对 TOL 敏感，但占比稳定在 43~44%**——这一点很重要：**占比结论是稳的，绝对数不是。**

### 1.3 实测基线（编码组用来对账）

```
各视频源帧数与隐患涉及帧：
  中海通20260508-161134   隐患涉及 38 帧   （时长 476.73s）
  中海通20260508-161153   隐患涉及 28 帧   （时长  96.17s）
  中海通20260508-161157   隐患涉及 25 帧   （时长 330.53s）
  中海通20260508-161201   隐患涉及 87 帧   （时长 1005.10s）

TOL=2 下各类结果：
  D-5-3   85 → 69   (1.2x)
  D-5-2   36 → 30   (1.2x)
  D-1-3   26 → 12   (2.2x)
  D-3-3   25 → 23   (1.1x)
  D-5-1   14 → 14   (1.0x)
  D-3-6    7 →  7   (1.0x)
  D-1-7    2 →  2   (1.0x)
```

### 1.4 验收标准

- 事件总数落在 **155~159**（TOL=2 或 3）
- D-1-3 事件数 ≤ 12
- 输出须同时保留帧级与事件级两套计数，**不得只报一个**

## 二、M2 · 隐患置信度分级（本次最重要的发现）

### 2.1 实测信号

D-5-3 在 TOL=2 下有 69 个事件，其**跨度分布**：

```
跨 5 帧：3 个
跨 3 帧：10 个
跨 1 帧：56 个   ← 占 81%
```

**81% 的 D-5-3 事件只在单帧出现过。**

### 2.2 判读

平均抽帧间隔约 **4.6 秒**（415 帧 / 1908 秒）。在这个采样密度下，**一个人若真的站在吊物下方，通常会被连续多帧捕获**。只出现一帧，说明：

- 要么人恰好只在那一帧的位置进入危险区（可能但概率低）
- 要么**VLM 在那一帧误判**（看到画面里有"人"和"吊物"就报了关系）

对比 D-1-3 跨 22 帧的持续状态，D-5-3 的单帧闪现特征非常像**偶发误报**。

⚠️ **这是推断，不是结论。** 需要用 M3 的几何判据硬校验后才能定性。

### 2.3 规格：给每个事件打置信度标签

```
frame_count >= 2  -> confidence = "high"   （多帧持续，可信）
frame_count == 1  -> confidence = "low"    （单帧闪现，需复核）
```

**并在报告里分两档给数**：

```
D-5-3：事件 69 个
  其中 high（≥2 帧）13 个
       low （单帧） 56 个   ← 标注"待几何校验"
```

这样甲方看到的就不是"69 条隐患"，而是"**13 条确认 + 56 条待查**"。这个差别是决定性的。

### 2.4 ✅ 已完成的交叉验证（实测，不是推断）

几何层重跑后已产出独立结果，与 VLM 结论三方可比：

```
D-5-3：VLM 帧级 85 条 / VLM 事件级 59 个 / 几何层 32 条
```

**32 与 59 属同量级（0.54 倍）→ 判定：不是幻觉。**

但也要注意：**59 个事件里约 27 个（46%）几何上不成立**。所以"单帧事件=误报"这个推断**不能一刀切**——部分单帧事件是几何成立的（可能人真的快速通过危险区）。

**修正后的口径**（取代 2.3 的纯推断版）：

```
D-5-3 事件 59 个
  几何成立        32 个   ← 高置信
  几何不成立      27 个   ← 需人工复核（其中大部分是单帧事件）
```

编码组应把 `geometry_ok` 与 `frame_count` **两个维度交叉**，不要只用其中一个。

### 2.5 验收标准

- 每个事件必须带 `frame_count`、`confidence`、`geometry_ok` 三个字段
- 报告必须分档给数，不得只给总数
- 不得把"单帧"直接等同于"误报"——必须结合几何校验结果

## 三、M3 · 几何判据（D-5-3 硬校验）

### 3.0 ⚠️ 先决前提：相机是静止还是运动

**这条决定用哪套判据，编码组开工前必须先确认。**

**诊断方法**：抽 20~30 帧跑 VGGT，看相对平移 ‖t‖。

- **相机静止**（工地固定摄像头，最常见）→ 走**射影解**（M3.1）
- **相机运动** → 射影解需要逐帧重估地面平面，成本高；且多视角重建在这个场景也不划算（吊物是大面积运动物体）

**当前判断：大概率静止，未验证。**

### 3.1 判据规格（射影解，不需要深度）

**核心原理**：判定「人在吊物下方」不需要吊物的深度，也不需要吊索方向。只需要：

1. **重力方向**（垂直消失点）—— 单帧可估（GeoCalib，pitch 中位误差 0.87~1.94°）
2. **地面平面** —— 静态相机下只剩 1 个未知数（相机高 h），可用**人高先验 1.7m + 框像素高** RANSAC 反解
3. 吊物地面投影点 = 过吊物中心的**铅垂射线 ∩ 地面平面**
4. 人脚点 = **人框底边**（不是框中心）对应的地面点
5. 比较两点的地面距离是否落在「吊物足迹半径 + 安全余量」内

**降级方案（若不做地面投影，纯 2D）** —— 直接采用 Singh & Seif 2026（arXiv:2607.16351）公式：

```
工人脚点 = 框底中心
净空比 r_clr = (y_foot_worker − y_bottom_load) / h_worker ，阈值 0.12
梯形坠落区：半宽从载荷底部 w/2 + 30px 线性扩展到地面 w/2 + δ_lat
           δ_lat = v_eff · t_fall ， t_fall = √(2h/g) ，漂移速度下限 0.4 m/s
垂直门控：脚点须在载荷底边下方 ≥ 40px
时序：1 秒滑窗内 ≥10/15 帧命中才判 Unsafe
像素-米代理 ρ = 中位工人像素高 / 1.75m
```

**输入**：`annotations.jsonl` 的 `qwen_detections`（字段 `label` / `bbox` 归一化 / `confidence`）——**不需要重新调 VLM**。

**输出**：每条 D-5-3 检出带 `geometry_ok` 布尔 + 证据字段（水平投影重叠率、垂直间隙、视角分支）。

### 3.2 已知的精度边界（写进注释，不要过度承诺）

- 纯 2D 框判定：Singh & Seif 实测 **P=0.523 / R=0.852**，人类标注者间 κ 仅 **0.308**
- 做地面投影：Chian et al. 2022（Safety Science）实测 **P=0.86 / R=0.83**
- 误差界：Δd ≈ (d²/h)·Δα；h=3m、d=15m 时 1° pitch 误差 → Δd ≈ 1.3m；多帧平均 + 人高平差后可望 0.3~0.7m
- ⚠️ Singh & Seif 的评测集是 **AI 合成视频**（SynthSite）+ CVPR **workshop**，迁移到真实工地要打折

### 3.3 现有代码的已知缺陷（编码组必读）

`industrial_hazard_coldstart/layers/geometry.py` 的 `find_person_under_load` 判据是
`contains(load, person)`（人框被吊物框包含 ≥85%）。

**这只覆盖"人被吊物框住"（俯拍 / 人在吊物上方）**。D-5-3 规范名是「人员站在吊物下方**/上方**」，地面视角下人框在 load 框**外下方**、两框不重叠，`contains` 永远返回 False。

现有单测构造的是大框包小框，所以测试通过但真实场景判不出——**这是死代码，必须重写**。

### 3.4 验收标准

- 测试用例**必须包含地面视角**（人框在 load 框下方、两框不重叠）
- 输出必须带证据数值，供人工复核
- 不得声称"厘米级 3D 判定"——定位是**风险提示级**

## 四、M4 · 评估口径修正

### 4.1 三条要改的

**1. GT 门槛**：`pallet` 在评估集里 gt=2，单个框命中/漏检就让 AP 在 0↔1 跳变。**gt < 10 的类不报 mAP**，改报"命中/漏检计数"。

**2. 宏平均口径**：COCO 规则是「无 GT 的类排除出均值；有 GT 但零检出的类计 0 并计入」。所以 7 类为 0 是**真实缺陷**，不能拿"缺类忽略"辩解。但必须三层同时报：

```
① micro-mAP（样本加权）为主
② macro mAP 保留，注明被几类零值主导
③ 逐类 AP + 该类 gt 数 + 置信区间
```

**3. 置信区间**：**image-level bootstrap**（按图像有放回重采样，**不要按框采样**——同图内框不独立，按框会低估方差）。1000 次起步，交付用 5000。

### 4.2 验收标准的三条修改

现在「档内取最差类」在 1:140 不均衡 + 7 类为 0 时等价于**永远 fail**。改为：

1. **安全关键类双门限**：整体（样本加权）达标 **且** person/helmet/vest/harness 逐类 ≥ 阈值；其余类只要求"不回归"
2. **GT 门槛过滤**：gt < 10 的类不参与打分
3. **CI 门限**：要求 **CI 下界** ≥ 阈值，杜绝噪声点估计过关

## 五、M5 · 时序判据（D-3-6 吊物悬停）

**现有代码可用**：`layers/temporal.py` 的 `detect_suspended_load`（272 行，含跨帧 IoU 跟踪 + 像素运动复核器），**已实现，只需接线**。

**重要修正**：**不要按 5~10fps 重新抽帧。** 当前抽帧间隔约 4.6 秒，连续 3 帧吊物位置不变 = **14 秒没动**，这比 2~3 秒滑窗是**更强**的悬停证据。稀疏帧判悬停反而更可靠。

**规格**：按 `source_id` 分组 → 对 `load` 框做跨帧 IoU 跟踪（IoU≥0.3，或中心距≤0.25 回落匹配）→ 轨迹持续 ≥3 帧且最大中心位移 ≤0.02（归一化）→ 判 `suspended`；若提供像素运动复核器且运动比 >0.15，降级为 `moving`。
