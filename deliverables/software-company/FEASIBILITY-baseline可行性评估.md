**原版的「三条约束」已被用户更正，本节据实修订。**

### 原文三条约束（历史记录）

1. 厂房视频仅文件名可见
2. 禁止解析内容
3. 禁止上传模型后端

### 修订后的真实约束（2026-09-17 用户口径）

**修订后的约束不是「不能做」，而是「只能经三条指定途径做」：**

- **途径一：本机部署的 YOLO** —— 离线、零网络，只能产出通道 A（目标框）
- **途径二：lab-server 上的 YOLO** —— 算力更强，同样只能产出通道 A；流程为「本地上传图片 → 远程推理 → 下载标签」
- **途径三：实验室私有多模态模型 API** —— 唯一能同时产出通道 A + 通道 B 的途径，也是毕设主通道

**逐条重估约束影响：**

- **约束 1（仅文件名可见）→ 已更正**：视频可解析。原版「这些视频对 baseline 数据贡献为零」的判断**不再成立**。
- **约束 2（禁止解析内容）→ 已更正**：抽帧是**允许且必要**的（否则无法把长视频压缩成可送模型的少量帧）。原版「最致命的一条、整条链路第一步就断」**已消除**。
- **约束 3（禁止上传模型后端）→ 已更正为「可上传到三条指定去向」**：VLM 标注可用。原版「通道 A 和通道 B 都产不出标注」**已消除**。
- **新增一条限制**：途径三的多模态模型因算力限制，**单次只能处理 1 分钟以内的视频**（见第九节）。

**推论（修订）**：在途径三授权下，**珠海 4 段视频（合计约 31.8 分钟）已成为当前唯一可用的真实长视频来源**，可跑「真实抽帧 → 真实标注」。厂房 1 小时视频仍属「未来资源」（未找到）。

## 三、两种 baseline 的区分（修订后判定）

### Type A：工程 baseline（链路可运行性）—— 可行 ✓（维持）

**定义**：证明「这条链路是通的、可复现的、可验收的」

**做法（证据更充分）**：
1. **抽帧**：用合成视频验证（可精确控制真值）。服务器已做过：8 秒合成视频，3 处场景切换精确对应 t=2/4/6 秒，4 张关键帧亮度指纹对齐
2. **标注**：用 mock provider 验证结构合规性
3. **数据集**：用 mock 资产跑通切分与 `data.yaml` 生成
4. **训练**：用 mock trainer，或在服务器跑 1–2 epoch 验证命令链
5. **交付**：一条命令端到端零报错 + 全套产物

**相对原版的增强**：本次增量已把「模型接入」从单一 OpenAI 兼容路径扩展为**可切换的三途径路由层**，并补齐时长护栏、编码约定、凭据预留与结构化输出；**292 个测试全绿**。工程 baseline 的证据比原版更硬。

### Type B：业务 baseline（真实检测性能）—— 修订为「拆两个子类」（见下）

#### Type B-1：通道 A 检测器性能（mAP50 / P / R）—— 仍不可行 ✗

**为什么仍不可行（原因已从「授权」变为「样本量」）**：

1. **训练数据为 0（框级）**
   - 珠海 4 段视频可解析，但**无标注**
   - 宿州仅 31 张且**无边界框**
2. **评估数据为 0**
   - 无黄金框标注 → 算不出 mAP50 / P / R
3. **31 张图不足以训练 12 类检测器**
   - 平均每类 **2.6 张**；检测器训练通常需每类数百张量级
4. **即使硬训，指标也无统计意义**
   - 验证集与训练集必然重叠；31 张分 train/val/test 后每个 split 只有个位数样本
   - 得到的 mAP50 是过拟合产物，**不可对外声称**

**修订要点**：授权解除**不会**自动产生边界框真值。Type B-1 的瓶颈是「**没有框标注**」，只能靠人工画框（或未来用真实 VLM 产出的框做初标再校）解决。

#### Type B-2：通道 B 隐患识别性能（P / R / F1）—— 由「不可行 ✗」修订为「有条件可测（尚未测）」

**为什么前提已解除**：

1. **数据入口解除**：珠海 4 段视频已确认可解析（第一节实测），可跑真实抽帧
2. **标注来源解除**：私有 VLM 途径已授权且代码已接入（`PrivateVlmAnnotator` + `inference.py` 路由），可对真实关键帧产出隐患事件 JSON
3. **弱标签可用**：宿州 31 张图的**文件名自带隐患描述**，可做通道 B 端到端定性核对

**为什么仍不能算「已测」**：

- 截至修订时点**尚未对任何真实素材实跑过**（token 未配置，见第六节）
- 宿州文件名是**图片级弱标签**，不是**逐帧黄金标注**，不足以算严格 P/R/F1；要算严格指标仍需人工标注黄金集（P1-2）
- 隐患多为「缺失态」（未戴帽、未系带），检测器只能检实体，违规判定靠空间关联规则——**这一子类指标的成色取决于规则质量，不取决于检测器**

**修订后的准确表述**：**「通道 B 从『不可行』变为『可测』，但尚属『未测』；严格指标仍需黄金标注集。」**

## 九、新增限制：单次送模型视频 ≤ 1 分钟（本次新增）

**限制内容**
- 途径三的多模态模型（`qwen3-vl:30b-a3b-thinking-q8_0`）**因算力限制，单次只能处理 1 分钟以内的视频**。
- 注意口径：本系统实际送模型的是**关键帧图片**，不是视频流；「视频时长」是用户给出的**保守约束口径**，用于圈定单次处理的素材范围。

**系统如何应对**
- 在抽帧/送模型**之前**做**时长校验**（`check_video_duration`，位于 `hazard_annotation/inference.py`）：
  - 优先用容器精确时长；探测失败回退；两者都失败视为「**未知**」并放行（**不得把探测失败误判为超限**）
  - 校验结果落盘进 `extracted/summary.json`（含 `status` / `duration` / `limit` / `action` / 分段数 / 提示语 / 告警码）
- 超限处置策略**可配置**（`inference.on_over_limit`），已实现三值：
  - `warn`：告警但放行，并在结果中标记「结果可能不完整」
  - `error`：直接拒绝，附「怎么改」的指引
  - `segment`：不拒绝，计算并给出建议分段区间（每段留安全余量）

**用户口径（人工截取）**
- 用户明确：**「目前只是开发阶段，算力有限制，需要人工截取片段」**——即**系统不自动裁剪**长视频，而是**明确提示用户自行截取**。
- 因此**超长视频的正确处理方式是「先人工截取成 ≤ 1 分钟的片段，再喂给系统」**，而不是让系统静默放行或自动切段。

**对珠海 / 厂房视频的具体影响**
- 珠海 4 段（1:36 / 5:30 / 7:56 / 16:45）**每一段都 > 1 分钟** → 全部需人工截取后才能送途径三。
- 若未来拿到 1 小时厂房视频 → **必须先人工截取**成若干 ≤ 1 分钟片段，无法一次性送模型。

**待对齐的一点（如实记录，供决策）**
- 当前**示例配置**（`examples/hazard_lab_vlm_project/config/project.json`）里 `inference.on_over_limit` 默认写的是 **`warn`**；而用户口径更接近「**拒绝并给出人工截取指引**」。
- 二者不冲突（策略可配），但**默认值建议按用户口径调整为「拒绝 + 人工截取指引」**，`warn` / `segment` 保留为可选项。此项属配置层调整，不改动既有逻辑。

- 即使抽了帧，也没有标注来源。人工标注是唯一替代，但成本极高。

**三条叠加的推论**：**在厂房视频上，整条链路一步都跑不了。** 这 4 类数据在当前约束下只能作为「未来资源」登记，**不能作为 baseline 的输入**。

**三、两种 baseline 的区分（回答的核心）**

**Type A：工程 baseline（链路可运行性）—— 可行 ✓**
- 定义：证明「这条链路是通的、可复现的、可验收的」
- 做法：① 抽帧用**合成视频**验证（可精确控制真值）；② 标注用 mock provider 验证结构合规性；③ 数据集用 mock 资产跑通切分与 `data.yaml`；④ 训练用 mock trainer，或服务器跑 1–2 epoch 验证命令链；⑤ 交付：一条命令端到端零报错 + 全套产物
- 价值：证明系统可运行、可交付、可复现。对毕设答辩的「系统完整性」叙事完全够用。

**Type B：业务 baseline（真实检测性能）—— 不可行 ✗**
- 定义：给出「隐患识别的准确率/召回率」这类业务指标
- 为什么不可行：① 训练数据为 0（厂房视频不可用、珠海无标注、宿州仅 31 张且无框）；② 评估数据为 0（无黄金标注 → 算不出 P/R/F1）；③ 31 张图不足以训练 12 类检测器（平均每类 2.6 张）；④ 即使硬训，指标也无统计意义（验证集与训练集重叠，每个 split 只有个位数样本，mAP50 是过拟合产物）

**四、baseline 的合理范围与预期性能**

4.1 可测量的指标（现在就能测）
- 抽帧层：链路可运行性、抽帧压缩比、抽帧漏帧率、9 项计数完整性
- 标注层：知识库结构合规率、thinking JSON 解析成功率、单帧请求次数、断点续跑有效性
- 工程层：180 个测试通过率、阶段产物完整性

4.2 不可测量的指标（当前条件无法给出）
- mAP50 / Precision / Recall、隐患识别 P/R/F1、真实场景漏检率、端到端延迟 / FPS

4.3 关于「预期性能」的诚实回答
- **当前条件下无法给出有意义的性能预测。** 原因不是算力不够，是**没有真值**。
- 唯一可以负责任地说的是：链路跑通后，第一版模型的指标**大概率不会好看**，原因有三：① 单机位固定视角；② 类间混淆（`rigging`/`hook`/`load`）；③ 隐患多为「缺失态」，准确率取决于规则质量。

**五、关键限制与风险**
- **R1【高】数据入口关闭**：厂房视频不可解析 = 没有长视频数据源，整条链路第一步就断。
- **R2【高】标注来源关闭**：禁止上传模型后端 = VLM 标注不可用，人工标注成本高。
- **R3【高】无真值 → 精度指标全部不可信**：直接导致论文实验章节没有素材。
- **R4【中】宿州 31 张图无边界框**：只能做分类示例或 few-shot 参考，不能直接训练检测器。
- **R5【中】珠海视频状态不明**：时长未知、是否受同样约束未确认、4 段仅跨 27 秒。
- **R6【中】单机位固定视角**：泛化性天然受限，场景属性决定，非工程可解。
- **R7【低】本机无训练能力**：缺 torch/ultralytics，训练必须上服务器。

**七、建议的 baseline 定义（务实版）**
