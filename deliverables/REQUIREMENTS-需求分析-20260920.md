# 需求分析：工业隐患双场景 YOLO 冷启动标注与训练

- 文档类型：需求分析（从零重写版）
- 日期：2026-09-20
- 负责人：许清楚（产品经理）
- Language：中文
- Programming Language：沿用现有工程约定（Python ≥3.11，零新增第三方依赖；训练侧可选 Ultralytics）
- 项目名（snake_case）：`industrial_hazard_coldstart`
- 单文件交付，不建子目录

## 原始需求复述

甲方工厂有**未标注**的真实监控素材，覆盖**吊装作业**与**高空作业**两个场景，希望实现 **YOLO 模型的冷启动训练**：从零标注到低成本训练，跑通完整流程。需求拆为三块：

1. 区分并整理「高空作业」与「吊装作业」两个检测方向；
2. 设计**低人工成本**的标注方案（半自动 / 主动学习辅助），产出训练集；
3. 基于该训练集完成 **YOLO 冷启动训练**。

复用母项目 `traffic_cv_closed_loop/` 的**两段式标注**思路与工程骨架：先用便宜的 YOLO 初检筛候选帧，只把有候选的帧送给昂贵的视觉大模型复核纠偏，产出标准 YOLO 标签；再训练、再把困难样本回流，形成闭环。

## 第 1 节 需求的目标与范围

### 1.1 一句话目标

用「YOLO 初检筛候选 + 私有视觉大模型复核」的两段式半自动标注，以最低人工成本，为甲方两个作业场景（吊装、高空）从零产出可训练的 YOLO 数据集，并在 `lab-server` 上跑通一次 YOLO 冷启动训练与评估闭环。

### 1.2 本期范围（做什么）

1. 对甲方现存素材（珠海吊装视频 4 段、宿州吊装隐患照片 31 张）做编目、解码、抽帧与两场景分流。
2. 建立两个检测方向各自的**类别体系（label taxonomy）**，并给出与隐患知识库的映射关系。
3. 复用两段式标注骨架，产出标准 YOLO 标签（txt）+ 人工复核队列 + 标注记录（jsonl）。
4. 设计并落地**低人工成本机制**：候选帧筛选、不确定性采样、自动通过 / 人工复核分级。
5. 构建版本化数据集（`data.yaml` + `manifest.json` + 类别直方图 + 划分）。
6. 在 `lab-server` 上完成一次 YOLO 冷启动训练与评估，产出指标与困难样本回流清单。
7. 建立隐私护栏、环境探活与依赖诊断，确保真实素材不出网、零新增依赖、母项目代码不动。

### 1.3 明确的范围外（不做什么，逐条给理由）

1. **不做高空作业素材的采集与拍摄**。素材缺口是甲方侧问题，本团队无现场条件，只能接收素材。
2. **不修改 `traffic_cv_closed_loop/` 任何一行代码**。它是母项目资产，改动会破坏回归与示例的可信度；新能力以新增文件 / 新配置承载。
3. **不引入任何新增 Python 第三方依赖**。`pyproject.toml` 的 `dependencies = []` 是项目传统，保持零依赖才能保证本机可复现与离线可跑。
4. **不在本机 Windows 跑全量测试与真实训练**。本机仅做单测、冒烟、小样本验证；全量验证与训练一律上 `lab-server`。
5. **不接入任何公有云 / 第三方多模态 API**。真实工业素材的解析途径仅限本机 YOLO、`lab-server` 的 YOLO、实验室私有 VLM 端点。
6. **不自动执行视频分段**。私有 VLM 只处理图片，视频分段不构成本需求的必要动作，避免无谓复杂度。
7. **不做模型部署、推理服务化、实时告警**。本期只到「训练出可用权重 + 评估」为止，部署是后续独立议题。
8. **不把开源资源与自有资源混放**。工作区内 `own/` 与 `open/` 两棵子树硬隔离，避免许可与隐私污染。

### 1.4 分阶段

**必达（本期交付的硬指标）**

1. 素材可被正常解码与抽帧，两个场景完成分流并各自产出候选帧清单。
2. 两个场景各有一套明确的类别定义，并至少完成「吊装」场景的完整标注 → 训练 → 评估闭环。
3. 两段式半自动标注链路可跑通，人工只处理复核队列，产出可被 Ultralytics 直接读取的数据集。
4. 隐私护栏（端点策略）与零新增依赖、母项目零改动的约束全部满足，现有测试全绿。

**延伸（条件具备时做，不阻塞必达）**

1. 高空作业场景的完整闭环（依赖素材到位）。
2. 主动学习选样策略的参数化与对比实验（不同不确定性度量）。
3. 多轮闭环回流，比较新旧模型指标变化。
4. 隐患语义报告（id + evidence + 本地回填的 category / norm / action）的可视化交付。

## 第 2 节 核心功能点

按链路顺序编号。每条标注「复用母项目已有能力」或「需要新建」。

### F1 素材编目与两场景分流 —— 需要新建（少量）

- **做什么**：扫描素材目录，登记每个素材的路径、时长 / 分辨率 / 帧率、场景归属（吊装 / 高空）、来源（珠海视频 / 宿州照片），生成素材清单。
- **为什么需要**：甲方素材形态不一（视频 vs 照片、两个场景），先编目才能决定后续走「视频抽帧」还是「图片直入」两条路，也才能量化素材缺口。

### F2 视频抽帧与关键帧筛选 —— 复用母项目已有能力

- **做什么**：对视频做按 `sample_fps` 抽帧、按运动 / 像素差 / 场景切换 / 感知哈希去重筛出关键帧，输出候选帧图片与候选清单。
- **为什么需要**：31.8 分钟视频逐帧处理既无必要也昂贵，关键帧筛选是压低后续标注成本的第一道闸门。

### F3 通用 YOLO 零样本初检（候选生成）—— 复用母项目已有能力

- **做什么**：用通用预训练权重对关键帧做一次初检，按置信度阈值筛出「有候选目标」的帧，作为昂贵标注的输入。
- **为什么需要**：这是两段式的第一段——用便宜算力过滤掉大量空帧 / 无目标帧，把视觉大模型调用次数压到最低。

### F4 私有 VLM 复核标注（两段式核心）—— 复用母项目已有能力

- **做什么**：只把带候选的帧送给实验室私有 VLM，做目标的新增 / 删除 / 框纠偏，产出标准 YOLO 标签；模型返回与初检结果做差异比对。
- **为什么需要**：这是「低成本高质量标注」的核心。YOLO 提供召回，VLM 提供语义与纠偏，两者互补，避免全量人工精标。

### F5 隐患语义标注与知识库回填 —— 复用母项目已有能力（需适配场景）

- **做什么**：让模型只输出**隐患 id + evidence（证据描述）**，`category / norm_reference / action` 由 `hazard-detection/knowledge_base.json` 在本地回填。
- **为什么需要**：杜绝模型编造规范号；同时把「检测框」升级为「可读的隐患结论」，贴合甲方业务语言。

### F6 主动学习 / 不确定性采样 —— 需要新建

- **做什么**：在自动标注结果中，按置信度低、模型间分歧大、差异计数高等信号排序，优先把「最不确定」的样本送入人工复核。
- **为什么需要**：人工预算有限，把人的时间花在模型最不确定的样本上，单位人工收益最高，这是「低人工成本」的关键杠杆。

### F7 人工复核队列与精标 —— 复用母项目已有能力

- **做什么**：把冲突 / 低置信度 / 解析失败的样本写入复核队列，人工只看这些样本；复核结果回写标签。
- **为什么需要**：把人工量从「全量」降到「队列量」，且队列可追踪、可统计。

### F8 标签质量过滤与数据集构建 —— 复用母项目已有能力（含 `scripts/curate_video_batch.py`）

- **做什么**：按差异计数、最低置信度、最少标签数等阈值过滤噪声帧；产出带版本的 YOLO 数据集目录，含 `data.yaml`、`manifest.json`、类别直方图、train/val/test 划分。
- **为什么需要**：视频帧自动标注天然含噪，先过滤再训练，避免脏数据拉低冷启动效果。

### F9 YOLO 冷启动训练 —— 复用母项目已有能力（训练执行在 lab-server）

- **做什么**：以通用权重为起点，在构建好的数据集上执行 YOLO 训练，产出最佳权重、训练报告与指标。
- **为什么需要**：这是需求第三块「完成 YOLO 冷启动训练」的直接落地。

### F10 评估与困难样本回流（闭环）—— 复用母项目已有能力

- **做什么**：评估新权重，导出困难样本清单与下一轮任务建议，把困难样本回灌到抽帧 / 标注环节，形成闭环。
- **为什么需要**：冷启动只是第一轮，闭环机制决定模型能否持续变好。

### F11 隐私护栏与端点策略 —— 复用母项目已有能力

- **做什么**：配置加载阶段强制端点策略（默认仅本机 / 内网，公网端点必须显式白名单），从源头阻断「改个 base_url 就把真实素材发到公网」。
- **为什么需要**：素材不出网是硬约束，护栏必须在配置层，而不是靠人记得。

### F12 环境探活与依赖诊断 —— 复用母项目已有能力

- **做什么**：提供 `doctor` / `probe` 类检查，验证配置、环境变量、私有 VLM 端点可达性、YOLO 可用性。
- **为什么需要**：真实素材解析依赖外部端点与服务器环境，开工前必须先确认「路是通的」，否则会在跑批中途才失败。

### F13 双场景独立模型管理 —— 需要新建（编排层）

- **做什么**：为吊装与高空两个方向各自维护类别体系、数据集、训练配置与权重，互不干扰。
- **为什么需要**：两场景目标形态差异大，混在一个模型里会互相干扰；分开管理也便于高空素材到位后独立补齐。

### F14 交付可视化与报告 —— 复用母项目已有能力（可选）

- **做什么**：生成自包含 HTML 报告，展示检测框、隐患结论与复核队列。
- **为什么需要**：给甲方 / 评审一个可看的交付物，便于确认标注质量。

## 第 3 节 输入与输出

逐功能点列出。输入路径含中文，全链路必须支持中文路径。

### F1 素材编目与两场景分流

- 输入：`D:\WorkPlace\industrial-data\` 下的珠海吊装视频 4 段、宿州吊装照片 31 张（只做元数据登记，不解析内容）。
- 输出：素材清单（`manifest`），字段含 `source_id / path / scene / media_type / duration / resolution / fps / count`。
- 落地：项目 `workspace/inventory/` 下。

### F2 视频抽帧与关键帧筛选

- 输入：视频文件路径、`sample_fps`、去重阈值、`max_keyframes`。
- 输出：关键帧 PNG 图片目录 + 候选帧清单（jsonl）。
- 落地：`workspace/extracted/frames/` 与 `workspace/extracted/candidates.jsonl`，摘要写 `workspace/extracted/summary.json`。

### F3 通用 YOLO 零样本初检

- 输入：关键帧图片、通用权重路径、`detector_confidence`、`detector_iou`、`image_size`。
- 输出：每帧的初始检测框（label / bbox / confidence），随候选帧清单一并落盘。
- 落地：并入 `candidates.jsonl` 的 `detections` 字段。

### F4 私有 VLM 复核标注

- 输入：候选帧图片（**仅图片，不发视频**）、提示词模板、允许输出的类别集合、私有 VLM 端点与 token。
- 输出：标准 YOLO 标签（txt，`class x_center y_center w h` 归一化）、原始响应（json）、标注记录（jsonl）。
- 落地：`workspace/review/labels/`、`workspace/review/raw_responses/`、`workspace/review/annotations.jsonl`。

### F5 隐患语义标注与知识库回填

- 输入：模型输出的隐患 id + evidence、`hazard-detection/knowledge_base.json`。
- 输出：隐患报告（`scene_type / hazards[] / overall_risk / recommendation`），其中 `category / norm_reference / action` 来自本地回填。
- 落地：`workspace/hazards/report.json`。

### F6 主动学习 / 不确定性采样

- 输入：标注记录（含置信度、差异计数、复核原因）。
- 输出：按不确定性排序的复核优先清单（含排序分数与依据）。
- 落地：`workspace/review/priority_queue.jsonl`。

### F7 人工复核队列与精标

- 输入：复核队列（jsonl）。
- 输出：人工修正后的标签 + 复核状态回写。
- 落地：`workspace/review/review_queue.jsonl` 与对应 `labels/`。

### F8 标签质量过滤与数据集构建

- 输入：标注记录、过滤阈值（`min_confidence / max_added / max_removed / max_adjusted / min_labels`）、划分比例与随机种子。
- 输出：版本化数据集目录，含 `data.yaml`（`path / train / val / test / names`）、`manifest.json`、`class_histogram.json`、`quality_report.json`、`curation_summary.json`，以及 `images/{train,val,test}`、`labels/{train,val,test}`。
- 落地：`workspace/datasets/<dataset_version>/`。

### F9 YOLO 冷启动训练

- 输入：`data.yaml`、起始权重、训练超参（epochs / batch / imgsz / device）。
- 输出：最佳权重 `best.pt`、训练报告（指标 + 配置 + 数据摘要）。
- 落地：`workspace/runs/<dataset_version>/` 与 `workspace/runs/latest.json`。

### F10 评估与困难样本回流

- 输入：训练报告、评估集、困难样本判定规则。
- 输出：困难样本清单（jsonl）+ 下一轮任务建议（md）。
- 落地：`workspace/analysis/hard_examples.jsonl`、`workspace/analysis/next_cycle_tasks.md`。

### F11 隐私护栏与端点策略

- 输入：端点 URL、策略模式（`local_only / allowlist / any`）、白名单。
- 输出：配置加载期的放行 / 拒绝判定与明确报错。
- 落地：无独立产物，作用于配置校验阶段。

### F12 环境探活与依赖诊断

- 输入：项目配置、环境变量、探活用的样张。
- 输出：诊断报告（配置项、环境变量、二进制、端点可达性）。
- 落地：`workspace/probes/` 与诊断输出。

### F13 双场景独立模型管理

- 输入：场景标识（S1 吊装 / S2 高处）。
- 输出：每个场景独立的类别定义、数据集版本、训练配置与权重索引。
- 落地：每个场景一份配置 + 独立 `workspace/` 子树。

### F14 交付可视化与报告

- 输入：标注记录、隐患报告、关键帧缩略图。
- 输出：自包含 HTML 报告。
- 落地：`workspace/visualization/`。

## 第 4 节 约束与假设

### 4.1 约束

**A. 授权与合规**

1. 联网下载开源资源已获授权，口径是**只进不出**：可以下载，但不得上传或携带任何私有素材。
2. 引入 SAM 类 / 开放词汇检测模型前，必须先确认其许可并留存结论。
3. 真实工业素材的解析途径仅限：本机 YOLO、`lab-server` 上的 YOLO、实验室私有 VLM API（`http://119.23.145.227:38091/api/generate`）。
4. 禁止公有云 / 第三方多模态 API 参与真实素材处理。

**B. 隐私与数据边界**

5. 素材不出网；端点策略默认 `local_only`，公网端点必须逐个显式声明白名单。
6. 助手不得用 Read 打开 `industrial-data` 下的私有素材文件内容。
7. 工作区内 `own/`（自有）与 `open/`（开源）两棵子树硬隔离，开源资源与自有资源不得混放。

**C. 环境**

8. 本机 Windows 只做小规模验证（单测、冒烟、小样本），不在本机跑全量测试与真实训练。
9. 全量验证与真实训练一律上 `lab-server`，工作区仅限 `/data/users/lyk`，GPU 为 RTX 4090D。
10. 不往 C 盘装包 / 下载任何依赖或模型。

**D. 技术**

11. `traffic_cv_closed_loop/` 一行不改，新能力以新增文件 / 新配置承载。
12. 零新增 Python 第三方依赖，保持 `dependencies = []`。
13. 现有测试必须保持全绿。
14. 中文路径必须全链路支持（素材路径、输出路径、配置路径）。
15. 私有 VLM 只处理图片，不处理视频；发送前必须确认待发文件确实是图片。

**E. 许可**

16. Ultralytics 为 AGPL-3.0，需评估其对甲方交付场景的传染性影响。
17. 任何新引入的模型 / 权重 / 数据集都要先核许可，再决定是否入库。

**F. 成本**

18. 私有 VLM 单帧实测耗时 2.2 秒 ~ 132 秒，波动 60 倍，根因是服务端排队；**标注成本模型必须按最坏情况（132 秒/帧）核算**。
19. 成本控制的杠杆是「减少送入 VLM 的帧数」（候选筛选 + 主动学习），而非压缩单次调用耗时。
20. 人工精标预算未知，需按「只处理复核队列」设计，不能假设存在全量精标人力。

## 第 5 节 可能存在的不确定点

每条说明「不确定的是什么」+「会影响什么决策」。区分需甲方答复 / 需实测。

**需甲方答复**

1. **两个场景的最终交付形态**：甲方要的是「检测框模型」还是「隐患结论报告」，还是两者都要？影响是否保留 F5 语义回填、以及交付物的定义。
2. **高空作业素材的来源与时间**：素材缺口由甲方补拍还是另找？影响高空场景能否进入本期必达，还是只能列为延伸。
3. **人工精标预算**：能投入多少人工小时？影响复核队列的规模上限与主动学习阈值的松紧。
4. **类别体系口径**：甲方认可的检测类别清单是什么？影响 F13 的类别定义与 KB 映射。
5. **规范号 / 隐患口径**：KB 的 58 条是否就是甲方认可口径？影响 F5 回填内容的权威性。
6. **验收标准**：冷启动训练达到什么指标算通过（mAP？召回？）？影响训练轮次与数据量目标。
7. **素材授权边界**：珠海视频与宿州照片可否用于训练并可交付权重？影响模型能否合法交付。

**需实测才能确定**

8. **视频解码可行性**：4 段视频能否正常抽帧、中文文件名 / 路径是否引发问题。
9. **私有 VLM 端点可达性与稳定性**：当前是否在线、排队常态耗时是多少。
10. **VLM 对工业场景的标注质量**：单帧输出的框与隐患 id 准确率如何，直接决定自动通过率。
11. **零样本初检召回**：通用权重能否有效筛出候选帧，决定成本模型是否成立。
12. **`lab-server` 环境**：ffmpeg、Ultralytics、CUDA 是否就绪，工作区权限是否满足。
13. **最优类别粒度**：粗粒度（如「吊钩」「吊带」）还是细粒度（按隐患 id）更适合冷启动，需要小样本对比。
14. **最坏成本是否可接受**：按 132 秒/帧、假设送入 VLM 的帧数为 N，总耗时的可接受上限需要一次试算确认。
