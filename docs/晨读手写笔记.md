# 智能交通路口 Qwen3VL -> YOLO 闭环训练项目晨读手写笔记

## 1. 一句话先记住

这个项目的本质不是“做一次检测”，而是：

**让 YOLO 先看一遍，让 Qwen3VL 再看一遍，最后把修正后的结果拿去继续训练 YOLO，形成数据反哺模型的闭环。**

可以背成一句话：

**先检，再审，再训，再回流。**

---

## 2. 项目总目标

本项目面向智能交通路口场景，解决的是：

- 视频很多，人工挑图太慢
- YOLO 初检有用，但不够稳
- 人工标注太贵，效率太低
- 训练和数据没有形成自动循环

所以项目目标就是：

1. 从视频或图片里筛出有价值样本
2. 用 Qwen3VL 帮助复核标注
3. 自动生成 YOLO 数据集
4. 继续训练 YOLO
5. 把困难样本再回流给下一轮

---

## 3. 项目最核心的三个 Skill

### Skill 1：`video_frame_extraction`

它负责：

- 读视频或图片帧
- 用 YOLO 初检
- 抽出关键帧
- 保存候选样本

一句话记忆：

**它是“筛样本”的。**

对应目录：

- `skills/video-frame-extraction/`

对应命令：

```powershell
python -m traffic_cv_closed_loop extract --config <config.json>
```

---

### Skill 2：`images_qwen3vl_annotation`

它负责：

- 读取关键帧9
- 读取 YOLO 初检结果
- 调用 Qwen3VL 复核
- 修正漏检、误检、错类别
- 输出标准 YOLO 标签

一句话记忆：

**它是“修标签”的。**

对应目录：

- `skills/images-qwen3vl-annotation/`

对应命令：

```powershell
python -m traffic_cv_closed_loop annotate --config <config.json>
```

---

### Skill 3：`yolo_closed_loop_training`

它负责：

- 根据修正后的标签生成数据集
- 切分 train / val / test
- 调用 YOLO 训练
- 输出指标和新权重
- 生成困难样本和回流建议

一句话记忆：

**它是“继续训练并总结问题”的。**

对应目录：

- `skills/yolo-closed-loop-training/`

对应命令：

```powershell
python -m traffic_cv_closed_loop train --config <config.json> --execute-trainer
```

---

## 4. 闭环流程怎么背

按顺序记：

1. `extract`
2. `annotate`
3. `train`
4. `hard_examples`
5. `next_cycle`

更容易记的中文版本：

**抽帧 -> 复标 -> 训练 -> 找难样本 -> 再回流**

这就是闭环。

---

## 5. 这个项目为什么要用 Qwen3VL

因为 YOLO 擅长：

- 快速检测
- 批量跑图
- 给出初始框

但是 YOLO 也有短板：

- 小目标容易漏
- 遮挡容易错
- 夜间和复杂场景不稳定

Qwen3VL 的作用是：

- 用更强的视觉理解做二次确认
- 检查 YOLO 有没有漏人、漏车、漏信号灯
- 检查类别对不对
- 检查框大致合不合理

所以要记住：

**YOLO 像第一轮筛查员，Qwen3VL 像第二轮审核员。**

---

## 6. 为什么最后还是要回到 YOLO

因为我们的最终目标不是只拿 Qwen 看图，而是要得到：

- 可部署的检测模型
- 可重复训练的数据集
- 可持续优化的权重

所以最终一定要：

**把 Qwen3VL 修正后的结果，转成 YOLO 训练数据，再反过来提升 YOLO。**

一句话记忆：

**Qwen3VL 帮忙标，YOLO 负责学。**

## 10. 配置文件要重点记哪些

### Qwen 部分

重点记：

- `qwen.provider`
- `qwen.base_url`
- `qwen.model`
- `qwen.api_key_env`

作用：

- 决定 Qwen 服务地址
- 决定调用哪个模型
- 决定 API Key 从哪里读

### YOLO 部分

重点记：

- `yolo.detector_weights`
- `yolo.weights`
- `yolo.device`
- `yolo.image_size`
- `yolo.epochs`

作用：

- 决定初检权重
- 决定训练权重
- 决定用 CPU 还是 GPU
- 决定训练轮数

### pipeline 部分

重点记：

- `frame_step`
- `min_detection_confidence`
- `review_confidence_threshold`
- `train_split / val_split / test_split`

## 12. 这个项目最值得讲的亮点

如果你要汇报，这几个亮点要记住：

### 亮点 1：不是单点功能，而是闭环系统

很多项目只做到“检测”或者“训练”，这个项目做到的是：

**检测 + 复标 + 数据集 + 训练 + 回流**

### 亮点 2：用视觉大模型辅助传统检测模型

这不是纯 YOLO，也不是纯 Qwen，而是两者协同。

### 亮点 3：支持 mock 和 production 两种模式

便于演示，也便于真实落地。

### 亮点 4：具备 Skill 化结构

适合 Agent 场景，可拆分、可复用、可编排。

## 13. 最容易被问到的三个问题

### 问题 1：为什么不直接用 Qwen3VL 检测

回答：

因为最终要得到的是可持续训练和部署的 YOLO 模型，Qwen3VL 在这里更适合做“审核和纠偏”，不是最终部署检测器。

### 问题 2：为什么要闭环

回答：

因为一轮检测不能持续进步，只有把训练结果中的问题样本重新回流，模型才会在下一轮更好。

### 问题 3：为什么要 Skill 化

回答：

因为 Skill 化以后，系统的每一步都能被明确复用、调用和扩展，适合 Agent 协作和工程化交付。

## 14. 一分钟晨读口播版

可以直接背：

> 这个项目是一个面向智能交通路口的 Qwen3VL 到 YOLO 的闭环训练系统。  
> 它先用 YOLO 对视频帧做初始检测，再用 Qwen3VL 对检测结果做二次复核、补标和纠偏，随后自动生成标准 YOLO 数据集，再调用 YOLO 进行训练或继续训练。  
> 训练完成后，系统还会输出困难样本和下一轮回流任务建议，从而形成“抽帧、复标、训练、回流”的持续优化闭环。  
> 项目同时支持 mock 演示模式和 production 真实模式，并以三个 Skill 的方式组织，便于 Agent 调用和工程化交付。

**本项目不是只做一次识别，而是让数据和模型形成持续互相提升的闭环。**
