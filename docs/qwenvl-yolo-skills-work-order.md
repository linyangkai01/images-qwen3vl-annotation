## 2. 任务描述

最近 Agent SKILLS 的工程化实践越来越成熟。与一次性 Prompt 或临时脚本不同，Skills 能把某一类可重复的工作经验沉淀为稳定、可检索、可复用的能力模块，避免每次执行任务时都重新组织上下文、重新描述流程、重新串联工具。

在智能交通路口场景中，YOLO 模型训练通常依赖大量人工标注，成本高、周期长，而且在小目标、遮挡、远距离、夜间或复杂天气场景下容易出现漏标与错标。为提升数据生产效率并构建持续优化能力，需要引入多模态模型 Qwen3VL 对 YOLO 初始检测结果进行二次校验、补标和纠偏，并将新增样本重新回流到 YOLO 训练流程中，形成从视频抽帧、视觉复标、训练评估到错误回流的闭环机制。

本工单目标是将上述流程标准化为一组可复用的 SKILLS，使开发人员只需给出最小必要输入，即可快速调用能力链路，完成交通路口视频数据处理、标签纠偏、数据集生成、模型训练与误差回流，显著提升研发效率与模型迭代效率。

## 3. 任务背景

### 3.1 SKILLS 的价值

Skill 本质上是一个包含 `SKILL.md` 的能力目录。该目录可进一步包含脚本、模板、资源文件和说明文档，用于向智能体明确说明：

- 该 Skill 适用于什么任务。
- 需要什么输入。
- 应按什么步骤执行。
- 产出哪些文件和结果。

一个成熟的 Skill 机制通常包括三个过程：

1. 发现：智能体根据任务名称、描述和上下文，判断是否存在可用 Skill。
2. 激活：当任务与某个 Skill 的适用场景匹配时，加载其说明和资源。
3. 执行：依据 Skill 中固化的流程调用脚本、模型、模板或外部工具。

这意味着经验不再只保存在某次上下文对话中，而是能够沉淀为团队长期可用的“数字化工作方法”。

### 3.2 业务问题

当前路口视觉模型训练主要存在以下问题：

- 视频数据体量大，人工逐帧筛选成本高。
- YOLO 现有模型可完成初筛，但对边缘样本、密集场景和长尾类别效果有限。
- 人工复核流程不统一，数据格式转换与版本管理容易出错。
- 标注、训练、评估和回流之间缺乏标准接口，难以形成稳定闭环。

### 3.3 建设思路

通过构建可复用的 SKILLS，将“视频抽帧 -> YOLO 初检 -> Qwen3VL 二次标注 -> YOLO 数据集生成 -> 训练评估 -> 困难样本回流”沉淀为标准作业流程，降低人工参与强度，提升样本质量与模型迭代速度。

## 4. 建设目标

### 4.1 总体目标

建设一套面向智能交通路口场景的 CV SKILLS 体系，支持使用 Qwen3VL 对 YOLO 初始结果进行复核和增强，构建 YOLO 的闭环训练链路。

### 4.2 具体目标

- 建立视频数据自动抽帧与目标片段提取能力。
- 建立基于 Qwen3VL 的图像级二次标注与标签纠偏能力。
- 建立 YOLO 数据集生成、训练、评估与困难样本回流能力。
- 形成统一的输入输出约定、目录规范和交付标准。
- 支持后续扩展更多交通场景 Skill，例如信号灯识别、事件检测、违停识别和车道占用分析。

## 6. 核心 Skills 设计

### 6.1 Skill 一：`video-frame-extraction`

**目标**

从交通路口视频中自动提取有效帧、目标片段和初始候选样本，为后续复标和训练提供结构化输入。

**输入**

- 原始视频文件或视频目录。
- 已有 YOLO 模型权重。
- 抽帧策略配置。
- 类别清单与置信度阈值。

**执行逻辑**

1. 调用 YOLO 对视频进行初步检测。
2. 根据时间间隔、目标置信度、类别命中率和场景变化幅度筛选关键帧。
3. 保存关键帧、时间戳、视频片段和初始检测框。
4. 输出待复核清单，供 Qwen3VL Skill 调用。

**输出**

- 关键帧图像目录。
- 对应时间戳与原视频映射文件。
- YOLO 初始检测结果清单。
- 待复核样本清单。

### 6.2 Skill 二：`images-qwen3vl-annotation`

**目标**

对关键帧进行细粒度二次识别和标签修正，将 Qwen3VL 的多模态理解能力用于纠偏 YOLO 的初检结果。

**输入**

- 关键帧图像。
- YOLO 初始检测框与类别。
- 类别定义、标注规则和 Prompt 模板。
- 可选人工复核阈值配置。

**执行逻辑**

1. 读取关键帧和对应的 YOLO 初始标注。
2. 将图像与任务描述发送给 Qwen3VL，请其判断是否存在漏检、误检、类别偏差或框偏移。
3. 对比 Qwen3VL 与 YOLO 输出，生成修正建议。
4. 将确认后的结果转换为 YOLO 标注格式。
5. 对低置信度或冲突样本写入人工复核队列。

**输出**

- 修正后的 YOLO 标注文件。
- 样本差异报告。
- 人工复核清单。
- 可直接进入训练的数据集目录。

### 6.3 Skill 三：`yolo-closed-loop-training`

**目标**

将修正后的数据集送入 YOLO 训练与评估流程，并对误检漏检样本进行回流，形成可持续迭代的训练闭环。

**输入**

- 标准化后的 YOLO 数据集。
- 训练配置文件。
- 历史模型权重。
- 验证集与评估指标配置。

**执行逻辑**

1. 按版本生成训练集、验证集和测试集。
2. 启动 YOLO 训练并保存权重、日志和评估结果。
3. 分析低召回、低精度和类别混淆样本。
4. 将困难样本回流到抽帧和 Qwen3VL 复标环节。
5. 生成下一轮增量数据任务清单。

**输出**

- 新版本 YOLO 权重。
- 训练日志与评估报告。
- 困难样本清单。
- 下一轮闭环任务清单。

## 7. 闭环流程设计

完整闭环建议按以下步骤运行：

1. 采集交通路口视频数据，并按日期、点位和时段归档。
2. 使用 `video-frame-extraction` 从视频中筛选高价值关键帧和目标片段。
3. 使用 `images-qwen3vl-annotation` 对关键帧进行二次标注与标签纠偏。
4. 生成标准化 YOLO 数据集，并进行版本登记。
5. 使用 `yolo-closed-loop-training` 完成训练、评估和困难样本分析。
6. 将误检、漏检、长尾类别和复杂天气样本回流到下一轮数据生产。
7. 周期性比较模型指标，评估闭环收益。

## 11. 关键指标建议

建议在后续实施阶段重点跟踪以下指标：

- 数据生产效率提升比例。
- 人工复核工作量下降比例。
- 标签纠偏命中率。
- YOLO 模型的 `mAP50`、召回率和误检率变化。
- 闭环一轮从数据进入到新权重产出的周期时长。

## 12. 风险与注意事项

- Qwen3VL 的输出需要结合类别约束和格式校验，避免直接写入错误标注。
- 夜间、雨雪、逆光和遮挡场景应单独建立困难样本策略。
- 训练数据版本必须可追溯，防止回流样本污染评估结果。
- 人工复核队列应保留，以应对大模型与检测模型结论冲突的情况。

3. 最后接入定时调度或 Agent 编排，实现自动化闭环。
